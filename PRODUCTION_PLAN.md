# Production plan (written submission)

For production I would run Python scraper workers on AWS ECS Fargate, triggered daily by EventBridge Scheduler. Each casino would have a source configuration, source-specific parser, rate limit and validation tests. I would use ordinary HTTP requests for static pages and Playwright only when permitted sources need browser rendering. Robots rules, site terms and rate limits would be checked per source; blocks would trigger a stop and source review, never a bypass.

PostgreSQL on Amazon RDS would store casino details, source configuration, current offers, version history, collection timestamps and extraction outcomes. I would enable automated backups and point-in-time recovery, define retention, and test restores periodically. The static frontend could be hosted in S3 behind CloudFront, with an API only if the product needed dynamic filtering or accounts.

I would register a domain with a registrar, manage DNS through Route 53, and use AWS Certificate Manager for HTTPS certificates on CloudFront or an application load balancer. EventBridge would schedule the daily jobs. Each run would emit structured logs and metrics to CloudWatch: attempted/successful sources, missing fields, validation failures, duration and LLM cost. Alarms would notify me if the job failed, the success rate dropped, or the data had not updated by a deadline. Retries would be bounded and respectful.

The LLM would only structure extracted text; it would not be treated as a source of truth. I would validate responses against a schema, preserve evidence snippets and raw text, compare changes with the prior day's data, and send uncertain or unexpectedly changed offers to a review queue. I would budget roughly US$100–300 per month initially for modest cloud resources, database/backups, monitoring and moderate LLM use, excluding engineering time and unusually expensive sources. I would revise the estimate using measured workload and actual provider prices.
